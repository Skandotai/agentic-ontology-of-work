Ontology / Assurance

Feedback

Assurance since 1.0 aow:Feedback

Structured information, from people or systems, used to improve future behavior.

Records changes proposed as a result of Outcomes, reviews, and incidents, and who proposed them.

Attributes

AttributeTypeRequiredDescription
feedback_typeone of accuracy, policy, exception, preference, incidentWhat the Feedback is about.
issue_detectedtextWhat went wrong or could be better.
recommended_adjustmentsstring-listSpecific changes proposed.
severityone of low, medium, high, criticalHow urgent the Feedback is.
timestampdatetimeWhen the Feedback was given.

Every entity also has an id and a type, and may carry label, description, and the provenance facet: version, created_at, created_by, revision_of.

Relationships

RelationshipPoints toHow manyRequiredMeaning
feedback_onOutcome, Result, Action, PlanmanyyesWhat the Feedback is about.
provided_byActoroneWho gave the Feedback.
updatesPolicy, Memory, Plan, Skill, Actor, ContextmanyWhat the Feedback changed.

Example

Source: examples/claims-processing.jsonld. The example passes all validation checks.

{
  "id": "fbk-age-65",
  "type": "Feedback",
  "feedback_type": "exception",
  "issue_detected": "Claimants over 65 with pre-existing conditions reached an adjuster only after an automated decision had been drafted.",
  "recommended_adjustments": [
    "Add a rule exception for claimants over 65 with pre-existing conditions",
    "Record the exception pattern in the claims knowledge base"
  ],
  "severity": "medium",
  "timestamp": "2026-09-20T15:04:00Z",
  "feedback_on": [
    "outcome-cycle-time-2026q3"
  ],
  "provided_by": "person-adjuster-17",
  "updates": [
    "policy-high-risk-review",
    "kb-claims"
  ]
}
