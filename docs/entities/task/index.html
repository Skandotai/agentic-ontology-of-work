Ontology / Execution

Task

Execution new in 2.0 since 2.0 aow:Task

A unit of assigned work within a Plan, performed by an Actor filling a Role.

Gives "task" a single meaning. A Task is what gets assigned; an Action is what gets done; a Skill is what makes it possible.

Attributes

AttributeTypeRequiredDescription
statusone of submitted, working, input-required, completed, failed, canceled, rejectedWhere the Task is in its life.
due_bydatetimeWhen the Task must be completed.
descriptiontextyesLonger human-readable explanation.

Every entity also has an id and a type, and may carry label, description, and the provenance facet: version, created_at, created_by, revision_of.

Notes

Task states follow the Agent2Agent (A2A) protocol's task lifecycle so that AOW Tasks can be exchanged over A2A without translation.

Example

From examples/claims-processing.jsonld, which passes every validation gate.

{
  "id": "task-extract-84933",
  "type": "Task",
  "description": "Extract claim metadata from the claim form.",
  "status": "completed",
  "concerns": [
    "claim-84933"
  ],
  "assigned_to": "agent-validation",
  "requires_role": "role-eligibility-processor"
}
